# FAISAL M72 Experience-Learning Security Review

## Scope

M72 is a userspace service that turns selected execution experience into a reusable, bounded skill reference. The kernel records experience identity and artifact capability; the service owns semantic content and evaluation policy.

| Risk | Control |
|---|---|
| Unverified experience becomes reusable | Evaluation state must be explicitly verified before artifact publication; unverified results remain rejected. |
| Model output becomes authority | Artifact capabilities are generated by the kernel and checked by the kernel. Textual skill content never authorizes syscalls, tools, devices, network, browser, or deployment. |
| Artifact substitution | Retrieval requires the exact artifact ID and capability; stale capability testing returns `EACCES`. |
| Provenance loss | M72 links the persistent-memory digest to the kernel detailed-experience sequence and artifact source digest. |
| Correction leaves old skill active | The old index entry is marked corrected before a new experience/artifact is created and re-evaluated. |
| Failed reuse is treated as success | Reuse is recorded as a new experience; the service does not infer success from retrieval. |
| Content collision | M71 content digests and service key hashes separate entries; duplicate keys are rejected until correction explicitly supersedes the prior item. |
| Kernel ring loss | The kernel experience table is bounded; the service must retain its durable memory link and future versions must handle dropped-sequence signals explicitly. |
| Resource exhaustion | M72 bounds the in-memory index at 32 items and delegates durable-content bounds to M71. |

## Trust boundary

The evaluator is a policy component, not an oracle. A `verified` input in the reference fixture represents an externally supplied test decision; production systems must replace it with independent source verification, supervisor policy, and operator-approved gates. The artifact capability only protects kernel metadata retrieval and does not confer permission to execute the skill.

## Residual risks

M72 does not yet provide adversarial evaluator isolation, cryptographic signatures over policy decisions, multi-process index locking, distributed skill revocation, cross-session M72 index replay, semantic similarity attack resistance, or model poisoning defenses. M71 persists the content, but M72’s first index is process-local and the current test demonstrates same-service-session reuse. These are tracked downstream rather than hidden behind a learning claim.

## Conclusion

M72 adds a truthful experience-to-skill control path: record, evaluate, retrieve, reuse-record, correct, and re-evaluate. It does not create consciousness, retrain a foundation model, or grant an agent unrestricted authority.
