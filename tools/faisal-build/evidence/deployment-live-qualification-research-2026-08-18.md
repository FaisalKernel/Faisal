# FAISAL Live Deployment Qualification Research — 2026-08-18

| Source | Finding | M179 impact |
|---|---|---|
| [Kubernetes Deployments](https://kubernetes.io/docs/concepts/workloads/controllers/deployment/) | Deployment revisions and rollout history support controlled rollout and rollback, but an operator must still verify workload health and the intended revision. | Evidence must bind the candidate, previous active revision, canary observation, promotion, and rollback target to actual external orchestrator receipts. |
| [NIST SP 800-34 Rev. 1](https://csrc.nist.gov/pubs/sp/800/34/r1/upd1/final) | Contingency planning addresses recovery priorities, alternate processing, recovery procedures, testing, and restoration of essential services. | Live evidence must include restart, recovery, persistent-state integrity, time bounds, and operator disposition rather than only a QEMU replay. |
| [AWS Saga pattern](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/saga-patterns.html) | Long-running distributed transactions require compensating transactions when a step fails; compensation is distinct from simply restoring software bytes. | Irreversible external actions require an explicit compensation plan, idempotency key, execution receipt, compensation receipt, and residual-risk disposition. |
| [AWS rollback-safety guidance](https://builder.aws.com/content/3F04j2yRAAMBuPSPs50xwXZqg01/ensuring-rollback-safety-during-deployments) | Safe deployment rollback depends on compatibility, testing, and protocol rules; a binary rollback alone cannot undo incompatible state or external effects. | The validator requires migration compatibility, fencing, canary failure rollback, external-action compensation, stale-worker denial, and persistent-state verification. |

M179 adds a source-bound handoff package and validator. The package template is not production evidence. A completed report must be signed by an authorized deployment authority and include a real multi-host orchestrator identity, node/worker identities, fencing generations, canary/promotion/rollback receipts, live migration and restart evidence, and compensation receipts for irreversible external actions. The sandbox can only simulate these controls and must retain the production blocker.
